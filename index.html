DeepSeek-V4.1-Flash 模型结构

01 / Prefill 通信已实现

FlashComm

长 prompt 的 prefill 里，把 row-parallel 线性层后的 AllReduce 换成 ReduceScatter： 通信完成的同时序列也切好了，每个 TP rank 只处理约 S/TP 行 token。

02 / 投机解码已实现

DSpark

一次前向起草一整块 5 个 token，再交目标模型一次校验。讲清块并行草稿、Markov 条件头、 逐位置接受率，以及它为什么是 decode / 长输出优化而不是端到端优化。

TPOT −60.1%（A3 单机参考值）阅读 →
03 / 注意力并行默认关闭

DSA CP

V4.1 的稀疏注意力在 TP 组内按 query token 行切分：KV 整份复制，每个 rank 算全部 64 个头但只算 1/TP 行 token， 算完用一次 all-to-all 换回「全部 token × 本地头」。

--enable_dsa_cp · 要求 cp_size=1阅读 →
04 / Prefill 省算实验 · 精度有损

SWA Bounded Replay

CED 架构里 decoder 层的全局 KV 全部借自第 20 层，自己只需要最近若干 token 的滑窗。 于是 prefill 时第 21–39 层只回放末尾 140 行。对照 DeepInfer 的无损实现，说明 xLLM 当前这版为什么有损。

05 / 显存换带宽默认关闭

Engram 主机侧卸载

V4.1 的 196B n-gram 查表参数在 W8A8 下每卡约 27.7 GiB 常驻显存。把表搬到 host 内存， 每步用一个融合 CPU 算子查表去量化，再把命中行回传。换来的是 HBM 预算。

这些页面怎么用

先说清楚它不是什么，省得读者找错东西。

适合
判断某个开关值不值得在自己的场景打开；查特性落在哪个文件、哪个符号；对齐术语之后再读源码。
不适合
当作部署手册或调参表。页面上的性能数字都绑定具体硬件、输入规模和并发，换条件就不成立。
数据口径
性能结论一律带硬件、并行配置、输入/输出长度和并发；精度结论带验证方式。缺哪一项就写明缺。
状态标签
已实现=代码在仓里；已实测=我们跑过并留了数据；未验证=没跑过；有损=会改变数值结果。
