04 / Prefill 省算 · DeepSeek-V4.1

SWA Bounded Replay：decoder 层的 prefill，只回放末尾一段

CED 架构说过：第 21–39 层的全局 KV 全部借自第 20 层，它们自己只需要最近 128 个 token 的滑窗。 既然如此，prefill 时这些层就不必把 prompt 的每一行都算一遍 —— 只回放末尾足够覆盖滑窗的一段就够。 这就是「prefill 激活 8B、decode 激活 16B」这句话的落地方式。

  • 精度有损
  • 实验特性 · 显式 opt-in
  • 只影响 prefill，decode 不变
01

一句话结论与适用条件

先说最重要的一句 xLLM 当前这版是明确有损的。模块 docstring 第一行就写着 「Explicitly lossy V4.1 prefill consumer compaction」，开启时还会打一条 warning。 它只保证末尾那段输出有效，前缀位置的 hidden state 是近似的。 不要用它跑精度评测，也不要用它做需要 prefix logits 的任务。
解决什么问题
prefill 时第 21–39 层对 prompt 的每一行都算一遍，但按 CED 的结构，这些层对远处的 token 本来就不需要逐行重算。
做了什么
第 20 层写完完整的 main / index 缓存之后，第 21–39 层只保留每个请求末尾 140 行 query，其余行直接丢掉。
为什么是 140
保留的后缀必须覆盖滑窗长度 + 最大回退长度。V4.1 的 window 是 128，留 140 是在它之上加一点余量。
什么时候别开
精度评测、需要前缀 logits 的任务、模型结构不是 40 层 / source 20 / window 128 的布局（会直接报错）。
02

机制：在第 21 层切一刀

实现要处理的几件事

  1. 挑行

    按每个请求的 seq_lens_q 取末尾 min(n, 140) 行，拼成一个索引张量， 对 hidden / pre_mix / positions / input_ids 做 index_select。 空 DP 副本保留框架要求的那一行 dummy。

  2. 改 metadata

    seq_lens_q 按 140 截断，max_query_len 跟着取 min， slot_mappings 里行数等于原始行数的那些才做 index_select —— 压缩过的 source 平面行数更少（比如 ratio 2），consumer 层不会改写它们。

  3. 重定基稀疏索引

    topk_idxs 要按每个请求丢掉的行数 drop 整体减去 drop， 负值（无效槽）保持不动。candidate_blocks 和 candidates 同步压缩。

  4. 对齐 DP 副本

    所有 DP 副本必须一起进，包括空副本 —— 只缩活跃 rank 会让 MoE 的 gather 尺寸对不上。 而且每个副本可能带多个请求，保留的行数不一定都是 140，所以要用 dp_all_gather 交换各副本的实际行数，再喂给后面的 MoE。

  5. 散回原位

    最后把结果 index_copy_ 回原来的行号，保持 executor 的输出索引不变。 生成消费的是最后一行，它仍在原来的位置上。

03

对照 DeepInfer：无损版本是怎么做的

DeepInfer 是 DeepSeek 自己的推理框架，它把同一个优化做成了无损的，差别值得单独看。

DeepInfer 的 README 把这个特性描述为：

reduce decoder prefill work by replaying only a bounded suffix … the retained suffix must cover the SWA window plus the maximum backtracking length.

对应的默认 V4.1 配置是 DEEPINFER_YOCO_PREFILL_TRUNCATION_MODE=compact 加 DEEPINFER_YOCO_PREFILL_KEEP_TOKENS=140，并在 model_runner 里有一条硬断言： 

assert window_size + DEEPINFER_MAX_BACKTRACKING_TOKENS <= DEEPINFER_YOCO_PREFILL_KEEP_TOKENS

关键差别：它重建了 SWA 可见域

DeepInfer 有两种截断模式，可见域完全相同，区别只在布局：

模式布局算多少用途
mask 保持 full 全量计算，只把矩形外的可见域整行置 -1 等价性对照基准
compact 真截断成 compact 行数减少，计算量真的下降 生产路径

两种模式在 C++ 侧共用同一个 yoco_swa_visibility 计算，所以保留区间内的 attention 数值一致。 边界层（n_prefill_layer）上把 metadata 从 full 视图切成 compact 视图， kv_swa_full_index_pivots 换成 compact 的 pivots，consumer 层照常读，拿到的就是截断语义。

这正是 xLLM 这版缺的部分：xLLM 只做了「挑行 + 改长度」，没有重算保留行的 SWA 可见域， 所以被丢掉的行里本该被看到的那部分就真的丢了。这就是 docstring 里 「Missing consumer SWA dependencies make this approximate」的含义。

它还验证了等价性

DeepInfer 带一个 examples/yoco/yoco_equiv.py，分两级： L1 只比较两种模式的 SWA metadata（不加载权重）；L2 跑端到端，逐位比对 logprob 与 top-K 输出。 加 --mtp 还会比对草稿头 main cache 的写入等价性。有这套脚本，才敢说「无损」。

两边的约束是类似的 DeepInfer 的 compact 模式要求：草稿目标层必须全在边界同一侧，且 Engram 不能出现在 consumer 层。 xLLM 的校验里也有同一条（engram_layer_ids 不得 ≥ 21）。两边遇到的是同一组结构约束。
04

启用方式与约束

--enable_swa_bounded_replay=true

对应 ModelConfig 的 enable_swa_bounded_replay，默认 false， 代码注释写明「Lossy V4.1 prefill experiment; enabled only by explicit runtime opt-in」。

启动期校验：不满足就拒绝加载

validate_swa_bounded_replay() 在分配模型权重之前检查，任一条不满足就抛 ValueError：

要求值
层数n_layers == 40
滑窗window_size == 128
候选源层candidate_source_layer_id == 20，且第 20 层是 Full 层
consumer 来源第 21–39 层的 main_kv_source_layer 全部是 20
Engram 位置没有 engram 层在第 21 层或之后

也就是说：它只对 V4.1-Flash 的那一套 40 层 / source-20 / window-128 布局成立，换模型就直接拒绝。

运行期：哪些批次会真的走这条路

  • 不走：处于 ACL 图里（acl_graph is not None），或带 execution state 的批次。decode 完全不受影响，包括图的捕获与回放。
  • 不走：这一批所有 DP 副本的最大 token 数都不超过 140 —— 没有可丢的行。
  • 走：其余情况，并且所有 DP 副本一起走，空副本也要进。

收益与验证强度

本页不给收益数字 我们还没有在这个开关上做过绑定条件的 A/B。没测过就不写数字。 可以说的是省算的上界：prompt 越长，被丢掉的行占比越高；在 N ≫ 140 时， 第 21–39 层（共 19 层，接近一半层数）的 query 行数降到约 140 / N。
项状态
功能实现已实现（xLLM 仓内，opt-in）
数值无损否，前缀 hidden 为近似
性能收益未验证，我们未做 A/B
精度影响量化未验证，没跑过数据集
decode 路径不变，含 ACL 图捕获/回放

上游状态

encoder 侧的 bounded replay 已在上游 vLLM 合入。 decoder 侧 —— 也就是 CED「prefill 减半」真正依赖的那一半 —— 上游 vLLM 还没合入； vllm-ascend 有实现，开启时要求 MRV2 等条件。我们也还没测过它的实际收益。

07

风险与待确认

  • 精度：前缀 hidden 近似的影响没有量化过。要用在生产前，至少先补一次数据集对比。
  • 不支持 prefix logits：只有末尾那行输出有效，需要中间位置 logits 的任务不能用。
  • 补齐路径：要做到无损，需要像 DeepInfer 那样重建保留行的 SWA 可见域（pivots），并配一套 mask / compact 等价性对比脚本。这是明确的下一步，当前没有。
  • DP 一致性：所有副本必须同进同出。改动这块时如果漏了空副本，MoE 的 gather 会尺寸不匹配。
