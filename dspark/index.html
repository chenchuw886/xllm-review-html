02 / Decode · 投机解码

DSpark：一次起草一整块，一把交给大模型校验

普通投机解码的草稿模型要串行跑 γ 次才能起草 γ 个 token。DSpark 用一个并行 backbone 一次前向就算出块内全部位置，再用两个极轻的头把「后一个词依赖前一个词」这件事补回来。 目标模型随后只做一次校验。

  • 已实现
  • A3 单机已实测
  • Decode / 长输出优化
01

一句话结论与适用条件

解决什么问题
decode 阶段每步只产出 1 个 token，但每步都要把整个 MoE 大模型跑一遍。算力利用率低，TPOT 被访存和下发开销主导。
做了什么
用一个 3 层的轻量草稿模型一次起草 5 个 token，目标模型一次校验这一整块，接受最长的合法前缀，并顺带拿到一个 bonus token。
什么时候开
decode 占端到端时延比例高的场景：长输出、中低并发。接受率越高，收益越大。
什么时候别开
短输出（起草开销摊不回来）、prefill 主导的场景。在我们的实测里 DSpark 会抬高 TTFT，它不是端到端无条件的赢。
三个层次不要混

① 投机解码：一个无损的 draft-and-verify 算法，接受与目标分布一致的最长草稿前缀。

② DSpark 论文的完整设计：半自回归块草稿 + 置信度调度的验证长度。

③ xLLM 当前实现：固定 5 token 的块草稿（并行 backbone + 低秩 Markov 头）+ 目标模型校验。尚未加载 checkpoint 的置信度头，也没有实现论文的硬件感知前缀调度器。所以本页不把论文里在线调度带来的收益算到当前实测上。

02

一次 decode step：从 anchor 到下一个 anchor

两个轻量头

Markov 头（默认 rank 256）：用一个 token-到-token 转移矩阵的低秩分解给出偏置 B(y) = W₁[y] @ W₂。循环 k=1..5：查 W₁ 得到 r 维向量，乘 W₂ 得到词表长度的 bias， 加到 Lₖ 上后 greedy argmax。全程没有 attention、没有 KV 更新、没有 norm / MoE。

Confidence 头（论文设计）：输入当前位置 hidden 和上一个 token 的 Markov embedding， concat 过线性层加 sigmoid，给出「在前面全部 accept 的前提下，第 k 个 token 能通过验证的概率」。 调度器据此提前截断验证长度，不去验证后面低置信的草稿。 xLLM 当前实现没有加载这个头，验证长度固定为 5。

03

两套 KV 缓存，谁写谁读

这是移植时最容易搞错的一块。

缓存谁生成谁读取
target KVCache target 在 prefill / verify 时生成 后续 target verify 读取有效历史
draft KVCache target 在 prefill / verify 时产生的有效上下文 hidden，经 draft 权重转换后写入 下一轮 draft forward 读取

  1. prefill：用 target hidden 初始化 draft KV

    target prefill 的指定层 hidden → main_proj / main_norm → 各 draft 层自己的 KV 投影 / norm / RoPE → 各 draft 层自己的 KVCache。 不拿 target 的 prefill KV，而是拿 target 的 hidden_states 来构造 draft KV。 target 的 KV 仍然保留，供后续 verify 使用。

  2. verify：用有效前缀的 target hidden 更新 draft KV

    「有效 token 的 hidden」指 verify 输入端有效前缀的 hidden，与本轮输出错开一位。例如： verify 输入 [anchor, d0, d1, d2, …]，本轮输出 [d0, d1, correction]， 则用来更新 draft KV 的是 [anchor, d0, d1] 的 target hidden。

  3. 下一轮 draft：读已更新的 draft 历史 KV

    完成注意力计算，往复循环。

抽 hidden 的层号口径 V4.1 里 dspark_target_layer_ids 指的是层的输入（官方 reference 与 vllm-ascend 一致）。 如果照搬 V4 的写法去取层的输出，就会错位一层，表现为接受率明显偏低而单步成本不变。

接受率口径必须对齐后才能比 不同测试工具统计接受率的方式不同，数值可以差出十几个百分点。跨工具、跨框架比接受率之前， 必须先确认分子分母的定义一致，否则结论不成立。比性能时更稳的口径是单步成本 （TPOT × (1 + γ × 接受率)），而不是直接比 TPOT。

验证强度

  • 已实测：上述 A3 单机 DP4 W8A8 条件下的 TPOT / 吞吐，以及 951 次提案的逐位置接受率。
  • 已知代价：同一组测试里 DSpark 抬高了 TTFT。
  • 未验证：多机部署、其他并发与长度组合、短输出的盈亏平衡点。
05

当前实现的边界

  • 验证长度固定 5，没有置信度调度器。
  • 不支持 cp_size > 1。
  • 端到端验证目前集中在 Atlas A3 单机 DP4 W8A8。
  • 原生 DSpark 稀疏注意力模式需要显式的算子支持，默认走兼容模式。
  • 额外的草稿权重、KV cache、图状态和 workspace 都会增加显存占用。
  • 不支持缩减词表的 DSpark checkpoint。
图模式下的一个坑 稀疏注意力的 metadata 必须在每次图回放前刷新。移植时如果漏掉这一步，图里会一直用 warmup 时的 dummy 值， 表现为只在图模式下输出乱码，同时接受率掉到个位数 —— 两个症状同源。
