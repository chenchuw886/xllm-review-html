01 / THE IDEA

为什么能快：把“逐个生成”改成批量猜、一次验

大模型每次只生成一个 token，Decode 会反复读完整模型权重。投机解码先让更便宜的 drafter 猜一段，再由 target 并行验证；验收规则保证最终仍服从 target 分布。

普通自回归5 TOKENS

大模型要走 5 次

T1→T2→T3→T4→T5

每一步都依赖上一步结果，无法把未来 token 直接并到一次 forward。

投机解码DRAFT + VERIFY

便宜地猜一块，大模型验一次

draft × 5→target verify × 1→提交最长前缀

收益取决于三个量：草稿够不够快、一次能接受多长、target 有没有验证太多注定被拒的尾部。

平均每 token 延迟 = 草稿耗时 + 验证耗时 ÷ 每轮提交 token 数

02 / LANDSCAPE

主流方案，差别都在怎么猜下一段

点击方案看取舍。没有一种 drafter 永远占优：更强的依赖建模通常意味着更高的起草开销，更激进的并行又容易让块尾质量下滑。

03 / INSIDE DSPARK

DSpark：重活并行做，依赖轻量补回来

DeepSeek-V4-Flash-0731 的 xLLM 路径使用 3 层并行 drafter 和 rank-256 Markov head。前者一次算完整块，后者只做很轻的逐位采样。

04 / TRAINING

怎么训：冻结 target，专门训练一个会被接受的 drafter

训练目标不是独立成为更好的小语言模型，而是尽可能贴近 target 的条件分布，让更长前缀通过验证。

01Target 生成数据

从序列中随机采样 anchor，组成 γ-token 训练块。

02冻结大模型

target、词表 embedding 和 LM head 保持冻结。

03训练三部分

并行 backbone、Markov/RNN 顺序模块、confidence head。

04校准置信度

用 STS 校准前缀存活概率，供完整方案动态裁剪验证长度。

06 / WHEN IT WINS

更适合长输出；不是每个请求都该无脑开启

投机解码用额外 draft 计算换更少的 target step。输出越长、接受越高，这笔账越容易赚回来。

收益更明确

Decode 主导的长输出

  • 代码、数学、格式化生成等可预测内容
  • 需要压低 TPOT、提升单用户生成速度
  • 草稿接受长度稳定，输出足够长可摊薄固定成本
需要先测

短输出与高熵对话

  • TTFT 会增加，短输出可能来不及回本
  • 开放式内容接受率低时，draft 计算可能变成纯开销
  • 固定长度验证在高并发下可能占用过多 target batch
当前调度固定 5-token 验证

confidence head 与硬件感知前缀调度尚未接入 xLLM。

并行边界暂不支持 CP > 1

当前实测覆盖单机 16 卡、DP4；多机和更多并行组合仍需回归。

注意力算子默认走兼容模式

完整 DSpark SWA 语义需算子支持显式稀疏索引，并手动开启 native 模式。

显存比 target-only 更高

增加 drafter 权重、KV cache、图与 workspace；xLLM 已合并估算 target/draft KV，仍应保留运行期余量。

权重格式W8A8 已完成实机验证

支持共享或独立词表权重；reduced-vocabulary DSpark 暂不支持。

正确性边界验证保持 target 分布

真正收益必须同时看输出一致性、接受长度、TPOT、吞吐与峰值显存。

07 / START

xLLM 中，四个参数即可开启

DeepSeek-V4-Flash-0731 的 DSpark 权重已经包含三层 drafter、Markov head 和所需词表权重，不需要额外执行 MTP 权重导出。

一句话带走

DSpark = 并行块草稿的速度 + 一点轻量自回归的连贯性。长输出、接受率高时，它能用一次 target 校验换回多个 token；短输出和低接受率场景先做实测。
