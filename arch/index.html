01 / 模型结构

DeepSeek-V4.1-Flash 模型结构

这一页是其余几页的术语基础。它只做一件事：把这个模型的结构讲清楚， 并且始终分开两条口径 —— 论文口径（技术报告的设计意图）与 实现口径（代码里实际怎么跑）。两者在好几处不一致，混用会得出错误结论。 覆盖 CSA2 注意力、Compressor、Indexer、分层稀疏索引、mHC、Engram、DSpark 与多模态。

  • 40 层 CED 主干
  • 主干 552B + Engram 196B
  • hidden 5120 · 64 heads · head_dim 512
  • SWA 窗口 128
  • 部分昇腾字节数为推算
01

一页读懂

项要点
主干 40 层 CED（Causal Encoder-Decoder）：论文口径为前 20 层 causal encoder + 后 20 层 decoder；实现为单一顺序执行（见第 2 节）
参数 / 激活 主干 552B + Engram 196B；MoE 按 token 激活部分专家，激活参数 prefill 约 8B、decode 约 16B（论文口径）
CSA2 稀疏注意力 每层自算局部 SWA KV（窗口 128）；全局 main KV 只由 4 个 Full 层生成、被后续各层复用
分层稀疏索引 第 20 层建块级候选池；深层 Reindex 只在池内选 Top-512，索引成本与上下文长度解耦
配套机制 mHC 四流残差 · Engram n-gram 查表 · DSpark 投机解码
注册名 DeepseekV41ForCausalLM；词表 vocab_size = 129280

两件事决定了它为什么省

  • 两路 KV 与跨层复用

    每层都有局部 SWA KV（窗口 128）；全局 main KV 由 4 个 Full 层生成 —— 前 3 个（第 2 / 8 / 14 层）按 2:1 压缩，第 20 层 ratio 1 不压缩（未压缩直投）。 其余层按「是否自持 KV」「是否自建索引」组合成三种角色。 40 层里只有 4 层自持 main KV。

  • 分层稀疏索引

    第 20 层建块级候选池（每 8 个位置一 block，取 Top-2048 块），深层 Reindex 只在池内选 Top-512。 索引成本由候选池上限决定，与上下文长度解耦。 注意：4 个 Full 层仍对完整可见上下文打分 —— 只有第 24 层起的 Reindex 才被候选池约束。

论文 Figure 2 的那条曲线说明什么 上下文从 4K 增至 1M（256 倍）时，V4.1-Flash 的单 token decode FLOPs 仅约增加 1/4（论文口径， 按 BF16 / FP8 / FP4 = 1 / 0.5 / 0.25 加权）。 这是上面两件事叠加的结果，远小于前几代。
02

一次前向：从输入到输出

先用大白话走一遍整条路径，再往下看细节。

  • ① 文本和图片都变成向量

    每个文本 token 查词表（129280）变成一条向量。 图片由 DeepSeek-ViT 编码，3×3 pixel-unshuffle 把视觉 token 数降到 1/9， 再由 Aligner 映射到主干维度。图片向量放到对应位置，和文本向量拼成同一条输入序列。

  • ② 进层前：Engram 先把「要查哪些 n-gram」一次算好

    避免每一层重复做同样的哈希计算；层内只按需取用。

  • ③ 主干：40 层，每层重复同一套动作

    每层 = 注意力（CSA2）+ MoE（1 共享 + 384 路由 / top-6），两者都夹在 mHC 残差流之间。 理解注意力的关键是它有两份记忆： 局部记忆（SWA KV）每层自己算、只看最近 128 个 token； 全局记忆（main KV）只有少数几层生成、其它层直接复用。 CSA2 省显存省算力，靠的就是第二种「共享 + 复用」。

  • ④ 输出：预测下一个词

    最后一层输出经 RMSNorm → LM head，得到整个词表上的分数。

  • ⑤ 生成阶段：DSpark 投机解码

    用一个独立的小草稿模型一次多猜几个 token，交主模型批量验证。详见 DSpark 页。

CED 在实现里怎么体现

这是两条口径第一次分叉，也是最容易误读的一处。

代码里没有 encoder / decoder 两个类

40 层是同一个 ModuleList 的顺序循环，没有单独的 encoder / decoder 模块， 也没有额外的跨层投影分支。

但这不等于 CED 不存在。技术报告 §2.3.1 写明： 「CED 与 CSA2 结合时，decoder 中的 Full 层用第 L/2 层（encoder 末层）的 hidden 计算自己的全局 KV」。 而第 20 层 —— decoder 里第一个、也是唯一的 Full 层 —— 的输入正是第 19 层的输出， 其后第 21–39 层全部复用这份 KV。 顺序执行天然满足论文公式，不需要额外的投影分支。

真正依赖额外实现的是另一条省算路径：prefill 时 prompt 主体只跑前 20 层， decoder 只回放最近若干 token 补滑窗 —— 那是 SWA Bounded Replay 那一页的内容。

别说这句话

别说「它是 encoder-decoder 架构，所以要两套 KV」。只有一条顺序执行的层栈，KV 的分组是按层角色来的，不是按 encoder / decoder。

03

40 层结构与角色分配

实现侧用两个集合 + 「最近前驱」规则解析角色： kv_source_layer_ids 上挂 Compressor 与压缩 KV 缓存， index_source_layer_ids 上挂 Indexer； 消费者复用层号不大于自己的最近 source（max(s ≤ layer_id)）。

四种层角色

角色层号（0 基）算什么借什么写不写缓存
SWA‑only 0、1 只算 Q 和 128 局部窗口，无全局 KV 不借 不写任何全局缓存
Full 2、8、14、20 Q + SWA KV；Compressor 产出 main KV；Indexer 建 Top-K 索引 不借 —— 本层就是 source 写：main KV、indexer K、Top-K 索引
Reindex 24、28、32、36 Q + SWA KV；不重压 main KV，但用自己的 Indexer Q 重选索引 第 20 层的 main KV 和它的候选池 只写 Top-K 索引，不写 KV
Reuse 其余 28 层 只算 Q 和 SWA KV，压缩与索引全不算 最近 source 的 main KV + 上一个 source 写好的索引 都不写

按层范围看

层范围全局注意力分组方式ratiolayer type

实现口径：compress_ratios 为什么有 43 项

checkpoint 的 compress_ratios 共 43 项 = 主干 40 层 + 3 个 DSpark 草稿层占位（尾部 3 个 0）： 第 0–1 层 0 → 第 2–19 层 2（18 项）→ 第 20–39 层 1（20 项）→ 草稿 3 层 0。 主干只消费前 40 项。

相关字段：kv_source_layer_ids=[2,8,14,20]、 index_source_layer_ids=[2,8,14,20,24,28,32,36]、 candidate_source_layer_id=20、engram_layer_ids=[1,14]。 xLLM 侧见 xllm/python/models/deepseek_v41.py 的 DeepseekV41Config 与 _parse_v41_compress_ratios。

别说这句话

别说「Reuse 层是推理时的近似」。训练时就是这个结构，不是推理阶段的省算技巧。

04

CSA → CSA2：三个维度同时用上，三处做简

长上下文的注意力成本有三个可相乘的维度： 条目大小、序列长度、层。CSA2 的关键是三个维度同时用上，并把 compressor 与 indexer 都做简。

维度CSA · DeepSeek-V4CSA2 · DeepSeek-V4.1
压缩 压缩率 m 时，每条 main KV 由 2m 条原始 KV 合成，相邻条目的源区间相互重叠 去掉重叠：每条 main KV 只由 ratio 个不重叠的源 token 合成，compressor 更简
位置 压缩时额外引入绝对位置编码，标记这 2m 条源 token 的位置 去掉绝对位置编码，压缩 latent 不再显式记位置；改为写缓存前做一次 RoPE 对齐
Indexer K 从 hidden states 走一条独立的压缩路径产生 由 main KV latent 线性投影 + 归一化得到（wk 作用在 512 维 latent 上），省掉独立路径
层维 基本未覆盖 —— IndexCache / YOIO / HySparse 都只解决单一维度 跨层共享 main KV 与 indexer K，同时允许层间复用 Top-K 索引，且「缓存共享」与「索引复用」解耦

一句话记忆：CSA 靠「压得更狠」省显存； CSA2 靠「压得统一 + 多设层复用」同时省显存与算力。 ratio 1 是 CSA2 的退化特例（不压缩直投）。

05

CSA2 单层数据流：两路 KV 并行汇入同一个内核

一层只做两件事：自己算 Q 和最近 128 个 token 的 SWA KV；借来 Full 层压好的 main KV。

别说这句话

别说「先算滑窗注意力，再算全局注意力，再把两个结果合并」。 两路 KV 是同一个内核的两个入参，不是两次注意力求和。

跨层共享的三样东西

共享对象谁写（source）谁读（consumer）非 source 层本层新增
压缩 main KV cache 仅 is_kv_source 层（2/8/14/20） 后续各层，取最近前驱 source 的 cache 0 —— get_kv_cache_spec 返回 None，不分配
indexer K cache 仅 owns_k（= kv source）层 非 owner 的 index source 读最近 kv source 的 .indexer.k_cache 0
topk_indices_buffer Full / Reindex 层 Reuse 层沿用上一个 source 写好的索引 0（Reuse 不写）

Compressor：main KV 是压出来的（仅 4 个 Full 层跑）

Compressor 是 CSA2「压」的那一半。只有 4 个 Full 层真的跑它， 把本层 attention 输入 x 压成一份共享的 main KV latent（head_dim=512）。 走哪条压缩路径由 compress_ratio 决定。

ratio = 2 · 第 2 / 8 / 14 层ratio = 1 · 第 20 层
分组 每 2 个 token 一组、组间不重叠，一组压成一条 main KV 无分组，一个 token 一行
投影 两路：wkv(x) 出 kv、wgate(x) 出打分。两路都在 fp32 下算，且 gate 投到完整 512 维（每通道一个门） 仅 wkv，走 bf16
池化 pooled = Σ member_kv · softmax(score)，逐通道独立门控加权。池化之后才做 RMSNorm 无池化、无门控。latent = RMSNorm(wkv(x))，RMSNorm 在投影之后
跨 chunk 状态 prefill 分块时，本块内没凑满一组的尾 token 先停进 state ring（kv_state / score_state），下一块取回补齐。因为分组不重叠，不需要处理重叠窗口 无 state
位置 写缓存前在组起点位置 group_idx × ratio 上做 interleaved-pair RoPE 写缓存前在各 token 自身位置做 RoPE（每 token 一份）

ratio 1 在语义上等价于未压缩的 main KV，只是改由 compressor 统一产出；decoder 第 20–39 层用它。

一个会咬人的实现细节 Compressor 的跨 chunk 状态与压缩边界的对齐会影响 chunked prefill 和 prefix cache。 另外：图模式下每步的稀疏注意力 metadata 必须在回放前刷新。 xLLM 移植时漏了这一步，图里一直用 warmup 的 dummy 值， 表现为只在图模式下输出乱码，并且与投机解码接受率掉到个位数同源。

Indexer 打分的实现要点

indexer K 由 main KV latent 经一次线性投影 wk 后再做归一化（k_norm）得到， 不是从 hidden states 另开路径 —— 这是 CSA2 对 CSA 的核心简化。 只有组边界 token（(position+1) % ratio == 0）才发布 K。

上游 NVIDIA 线上，weights_proj 是 ReplicatedLinear（无需跨 rank 归约）， 打分走 DeepGEMM 的 MQA kernel，head-sum 和 ReLU 都在 kernel 内部完成。 所以在那条实现里看不到 Python 侧的 ReLU、门控或 all_reduce —— 这些逻辑已下沉到 kernel。 Q 侧用 fused_indexer_q_rope_quant 一次完成 RoPE + 量化。

06

两级 Top-K：块级候选池 → 逐位置精选

即使大部分层复用索引，剩下的 indexer 仍可能反复扫描百万 token。 分层稀疏索引把深层 indexer 的搜索范围从「全部压缩位置」收紧到「候选池上限」。

参数值作用
index_topk512每 query 最终读取的压缩位置数
candidate_topk_blocks2048候选池保留的 block 数
candidate_block_size8每 block 的位置数
candidate_source_layer_id20建池层
index_n_heads / head_dim32 / 128索引侧注意力规模
indexer_kv_dtypeauto → fp8索引 K 缓存精度（上游可选 MXFP4，需特定硬件）；昇腾侧恒 INT8

算例：1M 上下文、单 token decode

第 20 层（建池层，ratio 1 不压缩）对全部约 1,048,576 个位置打分， 选出 2048 块 × 8 位 = 16384 个候选位。 深层 Reindex 的打分范围从「全部压缩位」收敛到「池内 ≤16384 位」， 每个 query 最终只读 Top-512 压缩位 + 128 窗口位。 encoder 的 3 个 Full 层（2/8/14，ratio 2）各对约 52 万个压缩位打分。

别说这句话

别说「所有 indexer 都与上下文长度无关」。 4 个 Full 层的打分仍与长度线性相关，这是总计算中仍随长度增长的部分。

07

mHC 与 Single-Pass「错位一拍」

mHC 是什么：4 条残差流 + 折叠 / 展开

mHC（Manifold-Constrained Hyper-Connections，流形约束超连接）把残差流维护成 hc_mult = 4 条并行拷贝，形状 (tokens, 4, 5120)。 Attention 与 MoE 各自夹在 hc_pre（4→1 折叠）与 hc_post（1→4 展开并混合）之间： 先折叠成 1 条喂给子层，算完再展开回 4 条混回残差。 混合系数经 Sinkhorn 双随机化（迭代把矩阵调到每行每列和都为 1）。

步骤子块 1 · Attention子块 2 · MoE
A · hc_pre（4→1） pre_mix = sigmoid(logits) + eps 加权求和；用上一拍传入的 pre_mix 错位一拍：直接用子块 1 的 pre_mix 折叠，无需等本拍系数算完
F · 子层 attn_norm → CSA2 两路 KV 稀疏注意力 1 共享 + 384 路由（top-6）；sqrtsoftplus 激活、noaux_tc 偏置校正
B/C · hc_post（1→4） out = post·x + Σ comb·residual，comb 经 Sinkhorn 双随机化 返回 ffn_pre 交给下一层

Engram 注入发生在子块 2 之前、完整 4 条流上，这样混合系数能看到被注入后的残差流。

Single-Pass = 把 post 融进下一层的 pre

代码注释直言：Every layer's post runs inside the next layer's fused pre。 落到实现就是 —— FFN 子块的 hc_pre 直接复用 Attention 子块已算出的 pre_mix， 由 mhc_shifted_post_pre 一次完成 post + 下一步 pre。

收益来自消除等待：系数错位一拍后，kernel 遍历每个 tile 时可以同时完成输入混合 并累积下一步的系数统计量，不必等本拍系数算完 —— 这就是 Single-Pass 相对 multi-pass 的收益。

部署融合 = Mega-mHC

部署期再把 residual update、input mixing、coefficient prediction 融成单个 kernel。 上游有门控条件（特定硬件 + hidden_size % 1024 == 0 + hc_mult == 4 + DeepGEMM 支持）， 不满足就回退到多 kernel 路径。 论文口径：激活访存从 (4n+4)d 降到 (2n+2)d。 xLLM 侧对应 mhc_shifted_post_pre_*。

08

Engram：把「记忆」从计算里拆出来

Engram 是一个条件记忆模块：把「记住静态知识」从层计算里拆出来，改由稀疏查表完成。 全模型 196B 参数放在表里，但每个 token 只稀疏访问其中极少一部分，几乎不增加每 token 算力。

  • ① 取 n-gram

    对文本 token 取 2 / 3 / 4 阶 n-gram；图像 token 不参与。

  • ② 压缩词表 + 多头哈希

    NFKC→NFD→去重音→小写→空白折叠得到压缩词表（约 99092 项，字段 engram_compressed_vocab_size）； 每个 head 把 n-gram 哈希进自己的桶。

  • ③ 素数桶查表

    {2,3,4} 阶 × 8 头，每头一张约 16M 项的表，表长取互不相同的素数。命中一条 FP8 表示。

  • ④ 投影成 key / value

    命中的表示经投影得到 memory key / value，key 对齐到 hc_mult 条残差流。

  • ⑤ 门控注入

    x' = x + gate · value，gate 由「memory key 与当前残差流的匹配度」经 sigmoid 得到。

论文口径实现口径
规模与放置 196B 参数近似对半放在 2 个模块（表长取不同素数，故非严格均分：engram_num_embeddings=[384006168, 384016682]）；每模块 {2,3,4} 阶、8 个哈希头、每阶总嵌入维 2048；嵌入表与 key/value 投影都用 FP8 放在第 1、14 层（engram_layer_ids=[1,14]），以平衡流水线各级显存
相对原始 Engram 的改动 ① 去掉短因果卷积；② 嵌入表更新改用动量 + Sinkhorn 平衡 代码侧不可核
offload 与预取 — 表可放 host 内存；确定性寻址使表项可预取，首个模块的预取与第 1 个 block 的计算重叠，消费前 join；查表结果反量化到 bf16。每请求保留最近 max_ngram_size−1 个 token 供图回放时补历史；表按 TP×DP 分片

xLLM 侧的主机侧卸载实现（含 DP 共享内存、融合 CPU 查表算子、以及它的代价） 单独一页：Engram 主机侧卸载。

09

DeepSeek-ViT + Aligner

视觉编码器
32 层、隐藏 1024、16 头、中间维 2816、patch 14，2D-RoPE，RMSNorm + SwiGLU。 图像经 3×3 pixel-unshuffle（downsample_ratio=3）把空间特征重排到通道维， 视觉 token 降为 1/9，再由 Aligner（MLP）映射到主干维度。
规模限制
max_image_tokens=1024、min_pixels=295936（= 544²）； 起止与换行用可学习嵌入 image_start / image_end / image_newline。
模态相关路由
图像 token 走独立的专家 correction bias（gate.bias_vl），与文本的 e_score_correction_bias 分开。 偏置只用于专家选择，输出加权仍用原始路由分数。
一个硬约束
图像 span 必须在 start_pos=0 的单次 chunk 内 prefill。

890 B/token 是怎么来的（论文口径）

论文给出「全局 KV 压到 890 B/token，约 V4-Flash 的 1/4；持久化缓存约 1/8」。 按技术报告的参数可以推出这个数，与官方数字吻合：

项构成字节
main KV 一条512 维 × 0.5 B（E2M1）+ 512/16 个 E4M3 scale288 B
indexer K 一条128 维 MXFP4 = 64 B + 4 B scale68 B
encoder 3 个 ratio-2 层3 × (288+68) ÷ 2534 B
decoder 第 20 层（ratio 1）288 + 68356 B
合计只有 4 个 Full 层持有890 B/token
890 B/token 不能直接用于昇腾上的容量规划

这个口径不含每层 128 窗口的 SWA KV（固定大小、与上下文长度无关）。 更重要的是：实现层的 packed record 字节数与此不同。 例如昇腾侧 indexer K 恒为 INT8，而不是论文口径的 MXFP4。

做 A3 / A5 的 KV 容量规划时，请按目标平台实际的缓存格式重新算， 或直接读启动日志里引擎报出的 KV block 数与单 block 字节数。 本页不给昇腾侧的绝对字节数：那需要按具体版本核对缓存布局，我们没有在当前版本上核过。

一个容易漏的参数 compress_rope_theta = 160000，比 rope_theta = 10000 大得多。 原因：一条压缩 latent 代表 ratio 个 token，位置更稀疏，所以要配更大的 theta。 xLLM 侧 ratio > 0 的层用压缩 RoPE 表（theta 160000 + YaRN）， ratio 0 的层用普通表（theta 10000、YaRN 关）。

DeepSeek-V4-Flash → V4.1-Flash：改了什么

V4.1-Flash 不是把 V4 放大，而是沿「长上下文的显存与算力」这条主轴做了一组结构替换。

组件V4-FlashV4.1-Flash效果（论文口径）
主干组织 — CED：前 20 层 causal encoder，decoder 全局 KV 由其末层产出 prefill 时 prompt 主体只需过 encoder 20 层，prefill 计算 ≈ 减半
注意力 CSA / HCA CSA2：去重叠压缩 + 去绝对位置编码 + indexer K 投影自 main KV 实现更简、训练更高效
跨层复用 无层维复用 Full / Reindex / Reuse 三模式 + 分层稀疏索引 全局 KV ≈ 1/4 vs V4-Flash
SWA 缓存 在「持久化 SWA KV」与「回放重建」之间混合取舍 SWA Bounded Replay（encoder 侧 + decoder 侧） 持久 KV ≈ 1/8 vs V4-Flash
残差 mHC（multi-pass，三 kernel） Single-Pass mHC + Mega-mHC 融合 kernel 激活访存减半
条件记忆 无 Engram 196B：n-gram 查表 + 门控注入 以查表替代部分计算
投机解码 MTP（深度 1） DSpark：3 层草稿，5 位置并行 + Markov / Confidence 头 解码吞吐提升（详见 DSpark 页）
主 KV 精度 FP8 main KV FP4 main KV：E2M1 + 每 16 通道 1 个 E4M3 scale，QAT 训练；SWA KV 仍 FP8 主 KV 存储 ≈ 减半

读法：这条演进线目标一致 —— 尽量把「随上下文长度增长的成本」挪到「与长度无关的常数」上。 CED 砍 prefill、CSA2 + 分层索引砍 decode 的索引与显存、SWA Bounded Replay 砍持久缓存、FP4 砍主 KV 字节。

SWA Bounded Replay 的上游落地状态要分两侧看 encoder 侧已合入上游 vLLM；decoder 侧（CED「prefill 减半」的前提）尚未合入。 xLLM 有自己的实现，但是显式有损的，差别在哪、为什么有损，见 SWA Bounded Replay 那一页。
