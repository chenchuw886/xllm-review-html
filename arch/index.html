DeepSeek-V4.1-Flash 的 40 层，是怎么把长上下文成本压成常数的

这一页讲清三件事：这个模型的层栈长什么样、它的「记忆」分成哪几份、每份在昇腾上占多少字节。 读完你应该能回答：为什么 40 层里只有 4 层持有全局 KV，为什么 decode 的计算量从 4K 到 1M 只涨约四分之一， 以及推理框架必须为它做哪些改动。

  • 官方 reference 与 vLLM 实现已核对
  • 昇腾字节数为推算，未在机器上实测
01

一页读懂

先给结论，细节在后面各节。

552B + 196B主干参数 + Engram 查表参数
~8B / ~16B每 token 激活：prefill / decode
1M支持的上下文长度，原生图文输入

V4.1-Flash 是一个 MoE 模型。主干 40 层，论文把这个组织方式叫 Causal Encoder-Decoder（CED）： 前 20 层称 encoder，后 20 层称 decoder。但它不是 T5 那种 encoder-decoder，它仍然是从左到右生成的 decoder-only 模型， 代码里就是 40 层顺序执行。叫 CED 的原因见 第 3 节。

最核心的改动在注意力，叫 CSA2。一句话：每层都自己算最近 128 个 token 的滑窗 KV； 但全局的 KV，40 层里只有 4 层生成，其他层直接复用。

官方给的效果是：上下文从 4K 增长到 1M（256 倍），单 token decode 的计算量只增长约四分之一； 全局 KV 每 token 890 字节，约为 V4-Flash 的四分之一。

贯穿全文的一个目标 把随上下文长度增长的成本，尽量变成和长度无关的常数。CED 砍 prefill 的层数，CSA2 加分层索引砍 decode 的显存和索引计算， FP4 砍 main KV 的字节数。
常见误解 不要说「它是 encoder-decoder 架构，所以要两套 KV」。它只有一条顺序执行的层栈，没有独立的 encoder/decoder 两个模块。
02

一次前向走什么路径

从输入到 logits，先把顺序对齐，后面才好定位每个特性落在哪一段。

  1. 输入变向量

    文本 token 查词表（词表 129280）。图片经 DeepSeek-ViT 编码，再用 3×3 pixel-unshuffle 把视觉 token 数降到九分之一， 拼进同一条序列。

  2. Engram 先算哈希

    进层之前，把这条序列要查的 n-gram 哈希一次算好，后面层里只取用。见 Engram 卸载。

  3. 过 40 层

    每层固定两个子块：注意力和 MoE，都夹在 mHC 的残差流之间。

  4. 出 logits

    最后过 RMSNorm 和 LM head。生成阶段可以挂 DSpark 做推测解码。

记住一件事 注意力有两份记忆。一份是局部 SWA KV，每层自己算，只保留最近 128 个 token； 另一份是全局 main KV，只有少数层生成，其他层复用。后面所有内容都在讲第二份记忆怎么生成、怎么复用、怎么检索。
03

40 层的四种角色

全片最重要的一页。层按「全局 KV 怎么来」分四类。

角色层号自己算什么全局 KV 从哪来
SWA‑only0, 1只算滑窗 KV不碰全局 KV
Full2, 8, 14, 20Q、滑窗 KV、压缩 main KV、indexer K、Top-K，全部自算并写缓存自己生成
Reindex24, 28, 32, 36Q、滑窗 KV，并自己再跑一次 indexer 重选 Top-Kmain KV 借第 20 层
Reuse其余 28 层只算 Q 和滑窗 KV，然后做注意力main KV 和 Top-K 都借别人的，不写任何全局缓存

按层范围看

  • 0–1：纯 SWA。
  • 2–19（encoder 剩下的 18 层）：分 3 组，每组 6 层 = 1 个 Full + 5 个 Reuse。这 3 个 Full 层的压缩比是 2，即每 2 个 token 压成 1 条 main KV。
  • 20–23（decoder 第一组）：1 个 Full + 3 个 Reuse。压缩比 1，不压缩。
  • 24–39：4 组，每组 1 个 Reindex + 3 个 Reuse，全部复用第 20 层的 main KV。

实现口径

对应 config 里三个字段：

kv_source_layer_ids    = [2, 8, 14, 20]
index_source_layer_ids = [2, 8, 14, 20, 24, 28, 32, 36]
compress_ratios        = [...]   # 43 项，末尾 3 个 0 是 DSpark 的 3 个草稿层占位

为什么叫 CED

论文说 decoder 的全局 KV 来自 encoder 最后一层的 hidden。看实现：第 20 层是 decoder 唯一的 Full 层， 它的输入正好是第 19 层（encoder 最后一层）的输出；第 21–39 层全部复用第 20 层的 KV。 所以顺序执行就满足论文定义，不需要额外的投影分支。

CED 真正的推理价值在 prefill：decoder 只需要 encoder 末层的信息来建全局 KV， 所以 prompt 的大部分 token 只要跑前 20 层，decoder 只需要回放最近若干个 token 来补滑窗 KV。 这就是「prefill 激活 8B、decode 激活 16B」的来源，也是 SWA Bounded Replay 这个特性存在的前提。

两个常见误解

Reuse 层不是推理时的近似。模型训练时就是这个结构，不是推理侧砍掉的。

decoder 没有独立投影把 encoder 输出变成 KV。实现里没有这个分支。

对推理框架意味着什么 KV cache 管理器不能再假设「每层一份同样格式的 KV」。有的层只有滑窗环形缓存，有的层有压缩 KV 加 indexer K， 大多数层根本不分配全局 KV。vLLM 里非 source 层的 get_kv_cache_spec 直接返回 None。
04

CSA → CSA2：改了哪四处

压长上下文 KV 有三个维度，V4.1 加了第三个。

维度手段谁做的
每条多大MLA：多头共享一条 512 维 latentV4 已有
有多少条压缩注意力：m 个 token 压成一条V4 已有
多少层各存一份跨层共享 main KV 和 indexer KV4.1 新增

CSA2 在 CSA 基础上改了四处：

  1. 压缩时源区间不再重叠。V4 一条 main KV 由 2m 个彼此重叠的 token 合成；V4.1 只用 m 个不重叠 token。
  2. 去掉压缩时的绝对位置编码，改为写缓存前在组起点做一次 RoPE。
  3. indexer K 改从 main KV latent 线性投影得到，不再从 hidden 另开一条压缩路径。
  4. 加上层维度。跨层共享 main KV 和 indexer K，并且「共享缓存」和「复用索引」是两件独立的事 —— 这就是 Reindex 这种「借 KV、自己选索引」角色的来源。
一句话 CSA 靠压得更狠省显存；CSA2 靠「压得更简单 + 多层复用」同时省显存和算力。
05

一层在 decode 时具体做什么

两路计算，一个内核。

常见误解 不要说「先算滑窗注意力，再算全局注意力，然后合并」。两路是同一个内核的入参，不是两次注意力再求和。

两个具体层的走查

  • 第 2 层（Full）：Q、滑窗 KV、压缩 KV、indexer K、Top-K 全部自算，全部写缓存。
  • 第 25 层（Reuse）：只算 Q 和滑窗 KV；main KV 读第 20 层的，Top-K 用第 24 层 Reindex 刚选出来的；它不写任何全局缓存。

Compressor 只在 4 个 Full 层跑

压缩比 2 时：每 2 个 token 一组，两路投影分别得到 kv 和门控分数，组内按逐通道 softmax 加权求和，再做 RMSNorm。 prefill 分 chunk 时，凑不满一组的尾巴 token 先存进一个小的 state ring，下一个 chunk 再补齐。 压缩比 1 时就是每 token 一条，RMSNorm(wkv(x))，没有池化。

实测踩过的坑 Compressor 的跨 chunk 状态和压缩边界对齐，会影响 chunked prefill 与 prefix cache 的实现。 图模式下，每步的稀疏注意力 metadata 必须在回放前刷新。 我们在 xLLM 移植时遇到过：metadata 没刷新，图里用的是 warmup 时的假值，表现为只在图模式下输出乱码。
06

分层稀疏索引

解决的问题：即使大部分层复用索引，Full 和 Reindex 层的 indexer 仍要对全部压缩位置打分。

  1. 第 20 层建池

    对全部可见位置打分，选出本层 Top-512；同时建一个候选池：每 8 个位置一个块， 取块内最高分，保留 Top-2048 块，最多 16384 个候选位置。

  2. Reindex 层只在池内选

    第 24/28/32/36 层先把池外位置的分数置为负无穷，只在池内选 Top-512。

  3. Reuse 层不跑 indexer

    直接用上一个 Reindex 层选出的 Top-K。

用 1M 上下文、单 token decode 算一下

层打分的位置数随上下文增长？
第 20 层（Full，ratio 1）≈ 1,000,000是
第 2 / 8 / 14 层（Full，ratio 2）各 ≈ 520,000是
第 24 / 28 / 32 / 36 层（Reindex）各 ≤ 16,384否
其余 28 层（Reuse）0否

所以仍然随上下文增长的，只剩 4 个 Full 层的打分。这就是「与上下文长度解耦」的具体含义。 indexer 参数：32 头、head_dim 128、Top-K 512。

常见误解 不要说「所有 indexer 都与长度无关」。4 个 Full 层的打分仍然与长度线性相关。
07

mHC 与 Single-Pass mHC

mHC 是 V4 就有的残差流设计，V4.1 改了系数的时序。

mHC 把残差流从 1 条扩成 4 条并行副本，形状是 tokens × 4 × 5120。 每个子层前先用 hc_pre 把 4 条加权折叠成 1 条喂进去，算完用 hc_post 展开回 4 条， 并按一个 4×4 混合矩阵把旧残差混进来。这个矩阵用 Sinkhorn 迭代 20 次，使每行每列之和为 1。

V4.1 的改动叫 Single-Pass mHC：每个子块算出的折叠系数，留给下一个子块使用。 注意力子块用的是上一层 FFN 子块算出的系数，FFN 子块用的是本层注意力子块算出的系数。 好处是折叠输入时不用等本子块的系数算完，可以把「上一子块的输出混合」和「下一子块的输入折叠」融成一个 kernel。 论文说部署时融成单个 Mega-mHC kernel 后，激活访存从 (4n+4)d 降到 (2n+2)d。

对推理的影响 残差流的激活是普通模型的 4 倍；hc_pre / hc_post 都是小算子，不融合就会成为 host 下发开销。 昇腾上对应 xLLM 的 mhc_shifted_post_pre_* 融合算子。
08

Engram：把静态知识改成查表

这里只讲模型侧；部署侧的显存卸载见 Engram 卸载。

  1. 取 n-gram

    对文本 token 取 2、3、4 阶 n-gram。图像 token 不参与。

  2. 规范化

    先把 token 规范化成一个压缩词表（大小写、重音等折叠后约 9.9 万）。

  3. 哈希

    用 8 个哈希头把 n-gram 映射进各自的表。

  4. 投影出 key / value

    命中的表项经投影得到 key 和 value。

  5. 门控加回残差流

    用 key 与当前残差流的匹配度算一个 sigmoid 门控，再把 value 加回残差流。

规模：196B 参数，分 2 个模块，放在第 1 层和第 14 层。表项是 FP8。

为什么能卸载到 host 查哪些表项只取决于输入 token，可以在进层前就算出来。所以表放 host 内存，提前预取，和第 1 层计算重叠。
decode 时的一个细节 n-gram 需要前几个 token 的历史，图模式回放时要每请求保留最近 3 个 token 来补齐。
09

视觉部分

标准做法：32 层 ViT，patch 14，2D-RoPE；3×3 pixel-unshuffle 把 token 数降到九分之一，2 层 MLP 映射到主干维度。

两个推理相关的细节：图像 token 在 MoE 里用独立的路由偏置； 图像片段必须在一次 prefill chunk 内处理完，不能被 chunk 切开。

KV 缓存族：谁持有、持有多少条

容量规划最常问的一节。设一个请求总长 T。

缓存哪些层持有条数随 T 增长？
SWA KV每层自持固定 128否
main KV只有 4 个 Full 层ratio 2 的层 T/2；第 20 层 T是
indexer K同样这 4 层同 main KV，维度更小（128）是
DSpark 草稿层3 个草稿层各一份 SWA固定窗口否

论文的 890 字节 / token 是怎么算的

main KV  一条 = 512 维 × FP4(0.5B) + 32 个 FP8 scale = 288 B
indexer K 一条 = 128 维 FP4 + 4 B scale             =  68 B
                                          每条合计   = 356 B

encoder 3 个 Full 层（ratio 2）: 3 × 356 ÷ 2 = 534 B
第 20 层（不压缩）            :     356      = 356 B
                                 合计        = 890 B / token

注意这个数不含滑窗 KV，滑窗是固定开销。

11

量化

官方权重：线性层 FP8，MoE 专家 FP4，Engram 表 FP8；main KV 是 FP4，训练时做了量化感知训练（QAT）；滑窗 KV 是 FP8。

官方表里的硬件门控（SM100 等）是 NVIDIA 线的，昇腾上按上一节那张表走。昇腾上另有 W8A8 权重路线。

V4 → V4.1 改了什么

V4.1 不是放大版，而是沿「长上下文的显存与算力」做了一组替换。

维度V4-FlashV4.1-Flash目标
主干组织普通层栈CEDprefill 只跑一半层
注意力CSA / HCACSA2 + 跨层复用 + 分层索引砍 decode 显存与索引计算
持久化 KV滑窗 KV 持久化到 SSDSWA Bounded Replay：需要时回放最近 128 个 token 重建官方说约为 V4-Flash 的 1/8
残差mHCSingle-Pass mHC可融成单 kernel
静态知识—新增 Engram（196B 查表）知识从层计算里拆出来
main KV 精度FP8FP4（QAT）砍 main KV 字节
推测解码预训练带 1 层 MTP，上线约两周后换成 DSpark预训练不带 MTP，DSpark 在预训练后单独训练—
Bounded Replay 的落地状态 encoder 侧已在上游 vLLM 合入。decoder 侧 —— 也就是 CED「prefill 减半」的前提 —— 上游 vLLM 还没合入； vllm-ascend 有实现，开启时要求 MRV2 等条件。xLLM 侧的实现见 SWA 回放，当前是有损的 opt-in 实验。
